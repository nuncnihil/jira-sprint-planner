# Jira Test Data Specification

This document defines the exact structure of test data for sprint planning POC.

## Overview

- **5 Initiatives** (4 feature + 1 Engineering Excellence)
- **6 Epics** (intentionally incomplete - 50% removed to simulate real planning)
- **~70 Issues** (Stories + Tasks) distributed across 3 sprints + backlog
- **Sprint 1** (Future, to be planned): 13 issues
- **Sprint 2** (Future): 20 issues
- **Sprint 3** (Future): 30 issues
- **Backlog**: 45 issues
- **Many unassigned tickets** - User must assign to epics or create missing epics

## Philosophy

This data is intentionally **messy** to simulate real sprint planning:
- Not all epics exist (user must create them)
- Many tickets unassigned (user must organize)
- Descriptions include hints about intended epic/initiative
- Forces realistic workflow: triage → organize → plan

### Realistic Backlog Scenario

The backlog simulates a **real, ungroomed backlog**:
- Mix of well-scoped and vague tickets
- Some tickets ready for work, others need refinement
- Clear initiative themes but missing epic organization

- Descriptions include hints: *"This relates to [epic area] for [initiative]"*
- No story points (backlog isn't estimated yet)
- Some tickets will need epic creation
- Some tickets can use existing epics

## Implementation Notes

### Sprint State
- **All sprints are "future"** - no active sprint
- User selects which sprint to plan in the tool
- No need to manage sprint start/stop in test data

### Story Points
- **No story points assigned** during creation
- Jira screen restrictions prevent setting points at creation time
- Points will be handled in future iteration (2-step update or manual)

### Epic Assignment
- **Only 6 out of 12 epics exist** in Jira
- ~40% of tickets assigned to existing epics
- ~60% of tickets unassigned with hints in descriptions

### Description Hints
Each unassigned ticket includes:
```
Description: [Functional description of the work]

Suggested Epic: [Epic Name]
Suggested Initiative: [Initiative Name]
```

### Labels
- All test data tagged with: `non-permanent-test-data`
- Engineering Excellence tickets also tagged with: `engineering-excellence`

### Data Quality
- **Intentionally messy** to test real planning workflow
- Forces user to organize, create epics, assign work
- Not perfect - reflects reality of sprint planning

## Usage

This specification is used by:
1. **`create-test-data.js`** - Creates issues in Jira following this structure
   - Creates 5 initiatives (or finds existing)
   - Creates only 6 epics (intentionally incomplete)
   - Creates ~70 issues with realistic names
   - Adds description hints for unassigned tickets
   - Tags all with cleanup label

2. **`verify-test-data.js`** - Validates data matches this spec
   - Checks initiative and epic existence
   - Validates distribution across sprints/backlog
   - Confirms unassigned ticket ratios

3. **Sprint planning tool** - Enables realistic planning workflow
   - User organizes unassigned tickets
   - User creates missing epics
   - User assigns work to initiatives/epics
   - Tests real-world planning scenarios
